# 04 — Датасет

## 4.1 Сбор нативных структур (позитивы)

Нативные структуры (класс `label = 1.0`) собираются запросом к RCSB API и скачиванием mmCIF. Жёсткие биофизические фильтры:

- метод: рентгеноструктурный анализ (X-ray diffraction);
- разрешение: $\le 2.0\,\text{Å}$;
- длина цепи: $50$–$700$ остатков;
- непрерывность: расстояние $C_i - N_{i+1}$ соседних остатков $\le 2.0\,\text{Å}$ (иначе цепь отбрасывается).

Итог пересборки 2026-08: **141 726 цепей** (лимит 200k, успешность ~71%).

## 4.2 Стратегии негативного сэмплирования

Для каждой нативной цепи генерируется **2 декоя** по взвешенной смеси стратегий (20% easy / 50% hard / 30% borderline, seed=42), имитирующих ошибки генеративных моделей:

| Стратегия | Искажение | Класс failure_mode |
|---|---|---|
| `easy_global_noise` | гауссов шум σ=1.5 Å на все атомы остова | 1 (Easy) |
| `easy_chain_break` | разрез цепи + смещение половины на 12–18 Å | 1 (Easy) |
| `hard_core_unpacked` | радиальное раздутие от центра масс на 10–25% (распаковка ядра) | 2 (Core/Compact) |
| `hard_false_compact` | разрез на 2–4 блока, повороты 20–120°, упаковка в сферу 4.5–8.5 Å | 2 (Core/Compact) |
| `hard_near_native` | анизотропное масштабирование осей ±2–5% + микро-повороты | 3 (NearNative) |
| `borderline_hinge_defect` | поворот хвоста вокруг случайного шарнира на 8–22° | 4 (Borderline) |
| `borderline_local_fragment_rotation` | поворот фрагмента 3–8 остатков на 6–18° вокруг оси фрагмента | 4 (Borderline) |

Классы: 0 = `positive_real` (натив), 5 = `unknown_negative` (зарезервирован, в данных отсутствует).

## 4.3 Таргеты вспомогательных задач

| Таргет | Как считается |
|---|---|
| `rmsd_target` | Kabsch-RMSD декоя до родительской нативной цепи (Å); у нативов 0 |
| `steric_target` | число клэшей виртуальных $C_\beta$ (< 3.5 Å, пары с $\|i-j\| < 3$ исключены) / длина; считается отдельным GPU-проходом `compute_targets.py` (идемпотентно) |
| `failure_mode_label` | стратегия генерации декоя / 0 для натива |

Таргет по водородным связям убран: ранняя версия детектора (неверный знак положения виртуального $O$) давала физически невозможные значения (~1.0 у нативов), а после фикса сам признак стал шумным регрессионным таргетом. `hbond_count` остался **входным признаком**.

## 4.4 Сплиты и предотвращение утечки

Разбиение 70/15/15 выполняется **по группам** (`group_id` = родительская цепь PDB ID + Chain ID): натив и все его декои всегда в одном сплите. При поэлементном разбиении конформации одной цепи попали бы в train и test одновременно, искусственно завышая метрики.

| | train | val | test | всего |
|---|---|---|---|---|
| Образцов | 297 624 | 63 774 | 63 780 | **425 178** |
| Позитивов | 99 208 | 21 258 | 21 260 | 141 726 |
| Групп | 99 208 | 21 258 | 21 260 | 141 726 |

Длины по сплитам сбалансированы (среднее ≈ 230, std ≈ 122, диапазон 50–698).

## 4.5 Формат манифеста и HDF5

Датасет описывается CSV-манифестом (`manifest_v1_split.csv`):

| Колонка | Описание |
|---|---|
| `split` | train / val / test |
| `source_h5` | путь к HDF5 **относительно директории манифеста** (датасет переносится между машинами без правок) |
| `h5_group_key` | ключ группы внутри HDF5 |
| `label` | 1.0 = foldable, 0.0 = декой |
| `group_id`, `parent_positive_key`, `strategy` | происхождение образца |
| `rmsd_target`, `steric_target`, `failure_mode_label`, `length` | дублируются из h5 для удобства |

В HDF5 каждая группа содержит датасет `coords` формы $[L, 3, 3]$ (float32, атомы $\{N, C_\alpha, C\}$) и атрибуты таргетов. Файлы: `positive_proteins.h5` (~1.6 ГБ), `negative_proteins.h5` (~3.3 ГБ), лежат в `dataset/` рядом с манифестом (git-ignored).

## 4.6 Конвейер сборки

```bash
cd dataset
python build_positive_dataset.py   # RCSB → positive_proteins.h5
python build_negative_dataset.py   # декoi → negative_proteins.h5
python compute_targets.py          # steric_target на GPU (оба файла)
python make_split.py               # манифесты + сплиты + статистика
cd ..
python -m preprocess.fit_pca       # PCA фронтенда по позитивам → dataset/pca_components.pth
```

Даталоадер (`dataset/dataloader.py`): батчи по 64, **бакетизация по длине** (ширина 50) для минимизации паддинг-отходов, кеш HDF5-дескрипторов на worker, сидированные `worker_init_fn`.
